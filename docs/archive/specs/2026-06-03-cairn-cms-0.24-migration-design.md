# 907.life → cairn-cms ^0.24.0: full-surface idiomatic migration

**Status:** approved (brainstorm), ready for plan
**Date:** 2026-06-03
**Supersedes brief:** the "migrate onto cairn-cms ^0.24.0" section of `docs/STATUS.md`

## Goal

Move 907.life from cairn-cms `0.6.0` (admin and auth only) to `^0.24.0`, the full
published surface, and end with a site that is idiomatic cairn throughout. Idiomatic
means 907 consumes the whole public delivery surface the way the reference consumer
(ecnordic-ski) does, with the site supplying its own render through the engine seam.

The guiding constraint from the owner: at the end of the migration, 907.life should be
a perfectly idiomatic cairn site. Two choices the original STATUS brief left open or
deferred resolve toward the canonical surface, not the minimal-departure path.

## Scope

In:

- Bump `@glw907/cairn-cms` to `^0.24.0` and reinstall from the workspace root.
- Schema-source-of-truth adapter (`defineAdapter` / `defineFields`).
- Engine render via `createRenderer` with an empty registry.
- Delivery read model (`createSiteIndexes`), public routes (`createPublicRoutes`),
  response helpers, and `CairnHead`.
- Per-concept URL policy in `site.config.yaml`.
- Content-graph wired full: committed manifest, build-time `verifyManifest`, link
  resolver, and a fail-closed dangling-link backstop.
- New `sitemap.xml` and `robots.txt` routes.
- Dependency prune of what the engine now owns.

Out:

- A `pages` concept. 907 stays posts-only (see Decision 1).
- Any redesign of the visual system, the typography, or the contact form behavior.
- The mdsvex `about` and `archives` route prose and components, beyond switching their
  loaders to the engine query.

## Resolved decisions

### Decision 1: about and archives stay in-repo mdsvex routes

907 models one editable concept, `posts`. The `about` and `archives` pages remain mdsvex
routes. Both embed Svelte components that a markdown concept cannot render: `about` carries
the contact form, `archives` carries the live post listing. The reference site keeps its
interactive routes (`/contact`, `/waiver`) as hand-built routes for the same reason, and
adds a `pages` concept only for genuine editable prose. 907 has no such prose, so a `pages`
concept would model nothing.

Posts-only also keeps the catch-all route unambiguous. Every entry the catch-all resolves
carries a date, so the page never branches posts-vs-pages, which sidesteps the
`EntryData`-has-no-concept sharp edge the ecnordic migration recorded.

The two mdsvex loaders switch their data source from `$lib/posts` to the new engine query.
`archives/+page.server.ts` reads the post list and tag counts from the engine.
`about/+page.server.ts` keeps its current shape (the contact form action is unaffected).

### Decision 2: content graph wired full, fail-closed now

The brief said decide the backstop posture at deploy. Idiomatic resolves it now. The
content graph is wired so it is live the day the first internal `cairn:` link lands:

- A committed manifest at `src/content/.cairn/index.json`.
- A `cairn:manifest` npm script backed by `scripts/build-manifest.mjs`, ported from the
  reference site's regenerate script.
- `verifyManifest` at module load in the delivery layer, so a drifted manifest fails the
  build.
- `buildLinkResolver(site)` threaded into render through `opts.resolve`.
- A surgical `prerender.handleHttpError` that rethrows only the dangling-`cairn:`-link
  error and leaves the existing `'warn'` default for every other prerender error.

907 ships with zero internal `cairn:` links today. The wiring is the readiness, and the
fail-closed handler is the guarantee that the first dangling link reddens the build rather
than shipping a page that 500s.

## Architecture

### Adapter: `src/lib/cairn.config.ts`

Rebuild on `defineAdapter`. One `posts` concept whose `schema` is a `defineFields`
declaration, the single source of truth for the editor form, the validator, and the
inferred frontmatter type:

- `text` title, required
- `date` date, required
- `textarea` description, required
- `freetags` tags (open vocabulary, distinct from a closed `tags` field)
- `boolean` draft

`render` becomes the engine renderer (see below). The backend block is unchanged
(`glw907/907-life`, the shared GitHub App). The `navMenu` block is unchanged.

The hand-rolled `src/lib/content-schema.ts` is deleted. The generated `validateFields`
coerces an unquoted-YAML `date` to a canonical string and enforces the declared field
shape. 907 accepts the engine's default date validation and adds no `refine` block. The
post create flow derives the filename from the `date` field, so an impossible calendar day
cannot enter through the date input in practice.

### Render: engine `createRenderer`

`src/lib/posts.ts` `renderPostHtml` is replaced by a renderer composed from the engine:

```
const renderer = createRenderer({}, {});
export const renderMarkdown = renderer.renderMarkdown;
```

The empty registry reflects that 907 has no directive components. The engine renderer
supplies remark-gfm, the sanitize floor, the heading-slug pass, the anchor hardening
(`rel="noopener noreferrer"` on `target="_blank"`, configurable through `anchorRel`), and
`cairn:` link resolution through `opts.resolve`. One renderer drives the public catch-all
page, the feeds, and the admin preview, so the editor sees what the published page renders.

Post body HTML shifts relative to the old plain pipeline: anchors gain a `rel`, headings
gain slug ids. This is acceptable. The byte-stability guarantee is on post URLs, not on
body markup.

### Delivery read model: `src/lib/content.ts`

A new module replaces `src/lib/posts.ts` and `src/lib/feed.ts`. It globs the posts corpus,
builds the typed index, verifies the manifest, and exposes the queries the public routes
read:

- `createSiteIndexes(cairn, siteConfig, { posts })` builds `site` and `posts`.
- `verifyManifest(buildSiteManifest(...), manifestRaw)` fails the build on drift.
- `buildLinkResolver(site)` is the resolver threaded into render.
- `postList()` and `postListByTag(tag)` map index summaries to list items, re-reading the
  authored `description` from the typed entry (the engine summary carries a derived excerpt,
  not the authored field).
- `feedItems()` maps posts to feed entries, capped at `FEED_MAX_ITEMS`, rendering each body
  through the resolver-aware renderer.

### Routes

- `src/routes/[...path]/+page.server.ts` and `+page.svelte`: the catch-all for posts.
  `createPublicRoutes(...)` returns `entries` and `entryLoad`. The page renders the post
  article and mounts `CairnHead` from `@glw907/cairn-cms/delivery/head`.
- `src/routes/[year]/[month]/[day]/[slug]/`: removed. The catch-all serves these URLs.
- `src/routes/tags/+page.server.ts` and `tags/[tag]/+page.server.ts`: kept, reading
  `posts.allTags()` and `postListByTag(tag)` from the engine. SvelteKit resolves these
  specific routes ahead of the rest parameter.
- `src/routes/about/` and `src/routes/archives/`: kept as mdsvex routes. Loaders switch to
  the engine query.
- `src/routes/feed.xml/` and `feed.json/`: collapse to `rssResponse` and `jsonFeedResponse`
  over `feedItems()`.
- `src/routes/sitemap.xml/` and `robots.txt/`: new, built with `sitemapResponse` and
  `robotsResponse`. The sitemap lists the home, the tags index, the static routes, every
  post, and every tag page. Robots points at the sitemap and disallows `/admin`.

### SEO head

`CairnHead` mounts in the catch-all page, fed by `entryLoad`'s `seo`. `entryLoad` reads
`image`, `robots`, and `author` from frontmatter where present. The site sets a default OG
image.

### Config: `src/lib/site.config.yaml`

Add the per-concept URL policy that reproduces 907's current URLs exactly:

```
content:
  posts:
    permalink: /:year/:month/:day/:slug
    datePrefix: day
```

Files are already named `YYYY-MM-DD-slug.md`, so this yields zero redirects.

### Build config and dependencies

- `svelte.config.js`: replace the blanket `handleHttpError: 'warn'` with a handler that
  rethrows the dangling-`cairn:`-link error and warns on everything else.
- `package.json`: bump `@glw907/cairn-cms` to `^0.24.0`; add the `cairn:manifest` script;
  prune deps the engine now owns once each is confirmed unused, candidates being
  `gray-matter`, the `remark` and `rehype` chain, `better-auth`, `drizzle-orm`, `carta-md`,
  and `mimetext`.
- Install with a full root `npm install` from `~/Projects/cairn/`, so the `@types/node`
  hoist that this site's `svelte-check` depends on is present.

## Module boundaries

- `cairn.config.ts`: the adapter. What 907 commits, the concept schema, the render. Depends
  on the engine and on `config.ts`.
- `content.ts`: the one delivery content layer. Every public route reads through it. Depends
  on the adapter, the site config, and the committed manifest.
- `config.ts`: typed views over `site.config.yaml`. Unchanged in shape.
- The route files: thin. Each reads `content.ts` or the `createPublicRoutes` handlers and
  renders. No parsing or globbing in a route.

## Testing and gate

- `npm run check` (svelte-check) reports 0 errors and 0 warnings.
- `vite build` succeeds, and the prerenderer enumerates every post through the catch-all.
- A drifted manifest fails the build (verified by editing a post and rebuilding before

- A live `/admin` dated-create smoke against a real Worker commits a post and the new URL

- `/2025/01/10/winter-prior-lake` resolves at its current URL, byte-stable as a URL.
